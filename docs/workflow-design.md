# Local workflow conventions

This file supplies the repository-specific context expected by the installed
Crack Planner and Implementer prompts.

- Implement only the selected commit unit and do not broaden it.
- Preserve user-authored and previously committed work.
- Use strict TypeScript and runtime validation for structured data.
- Keep generic logic company-agnostic; put company-specific facts in fixtures.
- Use deterministic code for normalization, routing rules, calculations, and
  scoring.
- Never turn a headline transaction valuation into enterprise value or
  security-level fair value without the required evidence.
- Prefer an explicit partial result or abstention over an invented input.
- Run the unit's listed verification and the aggregate check before declaring
  it ready.
- Do not configure remotes, push, open pull requests, merge, or deploy.
- Keep source PDFs, secrets, caches, and temporary output out of Git.
